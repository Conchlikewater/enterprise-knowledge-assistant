# V3 延期能力清单（Parking Lot）

> 状态：阶段 0 范围对齐修订完成，等待最终验收。
> 用途：记录明确不进入九月 P0 的能力、延期原因和重新评审条件，防止实施中顺手扩项。

## 1. P1 候选

| 能力 | 延期原因 | 重新评审条件 |
| --- | --- | --- |
| Draft 版本 | P0 调查报告只是任务结果，不需要版本化审阅 | 岗位或真实用户需要反复编辑与审批 |
| Approval/Reject | 需要身份、版本绑定和幂等副作用，超出当前最小 Agent 场景 | 正式归档或外发成为明确业务动作 |
| 正式报告归档 | 需要保留、删除、权限和审计政策 | 有明确归档用户故事和数据生命周期 |
| Investigation/Job 取消 | 协作式取消会扩大状态机和补偿矩阵 | 大文件耗时或真实用户证明取消必要 |
| 多 Worker | P0 只证明单机单 Worker 恢复 | 单 Worker 吞吐或队列积压有实测瓶颈 |
| Lease/Heartbeat | 主要解决多 Worker 所有权和崩溃接管 | 批准进入多 Worker 设计 |
| Generation/Fencing | 用于隔离旧 Worker 晚到写入 | 多 Worker、网络分区或多主机成为范围 |
| Redis/Celery/RabbitMQ | 当前 SQLite Job Queue 足够展示可靠异步基础 | SQLite 队列吞吐或锁争用报告证明不足 |
| PostgreSQL | 当前单机 SQLite 是有意边界 | 并发测试或多用户需求证明迁移价值 |
| 完整认证/RBAC | P0 是本地单用户作品集 | 需要真实用户、审批人或权限隔离 |
| 多租户 | 会影响所有查询、唯一约束和删除语义 | 明确企业租户场景和安全测试预算 |
| Reranker | 当前没有足够真实 bad case 证明必要 | 固定评测显示召回正常但排序稳定偏低 |
| Hybrid/BM25 上线 | 现有固定集实验低于 Dense | 新语料和受控实验显示稳定收益 |
| GraphRAG | 当前问题规模不需要图构建成本 | 明确关系型、多跳问题且 Dense 两轮不足 |
| 监控仪表盘 | P0 结构化日志和报告足够 | 持续运行环境需要长期趋势和告警 |
| Prometheus/Grafana | 会扩大部署与维护面 | 指标契约稳定且存在长期服务 |
| 外部 Trace SaaS | 先保证本地 Trace 可回放和隐私 | 明确工具选型、数据合规和成本 |
| 多 Agent | 当前单 Agent/Workflow 足以验证决策 | 出现可度量的角色分工收益 |
| OCR | P0 只支持文本型 TXT/PDF | 目标文档以扫描件为主且有许可数据 |

## 2. P0 明确不宣称

- 不支持网络分区、多主机或旧 Worker 晚到竞争；
- 不支持两个异步 Worker 同时运行；
- 不提供取消、审批、正式归档或越权审批防护；
- 不提供生产公网安全、完整身份、多租户或合规归档；
- 不宣称高并发、exactly-once 或分布式事务；
- 不宣称 Reranker、GraphRAG、Hybrid 已上线；
- 不把离线回放描述为真实 Provider 执行；
- 不把小规模合成评测推广为真实企业效果。

## 3. 重新进入规则

延期能力只有同时满足以下条件才可重新立项：

1. 有明确用户故事、岗位需求或实测瓶颈；
2. 能写出不与P0边界冲突的最小验收标准；
3. 明确修改模块、依赖、数据迁移、测试和回滚风险；
4. 不挤占P0修复、评测、README、演示和本人学习时间；
5. 获得用户单独批准。

本文件不是待办清单。没有触发条件时，延期能力保持不做。
