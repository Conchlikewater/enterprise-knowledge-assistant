## R7-B 已实现的最小处理契约

文件：`evaluation/r7_corpus_contract.py`，只在evaluation中，未改app/。

1. `ReviewedBlock`记录来源哈希、原PDF页码、结构块、课程身份和已经审查的文本。
2. `review_digest()`绑定上述全部字段；正文、身份或页码变动后，旧审查记录失效。
   这是完整性校验，不是身份认证或自动隐私证明。
3. `build_reviewed_chunks()`先校验整批再构造结果；拒绝越界来源/页码、重复块、
   未审核块、未知结构类别和命中的人员标签/调用方禁用词。错误不输出私密文本。
4. 复用现有自然边界+字符长度切分，不跨原页或结构块；不是Embedding语义切分。
   可选课程身份头也计入总字符预算。参数必须显式提供，目前没有国内正式默认值。
5. UUIDv5绑定来源字节、页码、块、审查摘要、算法版本、配置、块内序号与内容哈希。
   同一输入可复现；改配置或文本产生新ID，不沿用旧Gold。
6. `assert_same_corpus()`检查三组的完整Chunk内容与来源完全一致，不只比较数量。

23项构造数据测试通过：可复现/顺序无关、预算/页码、来源越界、过期审查、隐私错误、
元数据修改失效和三组语料不一致。它们**不是44份真实语料的端到端脱敏验收**。

## 学习与面试

本次核心知识点：**审过原文不等于完成评测；证据必须能稳定映射到实际检索的Chunk。**
否则改一次切分，原有Gold可能指向不存在的块，分数便不可复现。

面试要点：Gold不能只写“第几页”，因为检索系统返回的是Chunk。来源字节、清洗表示或
切分参数任一变化，都必须让稳定ID和旧Gold失效；否则评测会拿不存在或已变化的证据评分。
